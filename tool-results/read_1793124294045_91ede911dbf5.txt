   220→## A.4 Sub-map: lifecycle aset lengkap (MC §11) — state machine
   221→
   222→**Sumber:** MC §11 (procurement/registration → identification → QR/barcode generation/printing → inspection/readiness → reservation → picking → testing → dispatch → event use → return → condition/damage → repair/maintenance/calibration → retirement/disposal). Semua state/transisi **PROPOSED/TARGET**, implementasi Phase 13 (REQ-045).
   223→
   224→**Cakupan tier:** state machine penuh = **maxRider/ISOrider (Phase 13)**. Di **miniRider hanya subset register dasar**: `ASM-S01 registered` + `ASM-S02 identified` via CRUD aset & set template (Phase 8) — **tanpa reservasi/inspeksi/dispatch/maintenance** (✗ mini). Mini tidak mengenal state di bawahnya.
   225→
   226→### A.4.1 State aset
   227→
   228→| ID | State | Definisi | Bukti/evidence wajib | Aktor utama |
   229→|---|---|---|---|---|
   230→| ASM-S01 | `registered` | Aset terdaftar di asset register (procurement/registration): kategori, model, serial, ownership | record registrasi | P-05 |
   231→| ASM-S02 | `identified` | Identitas unik terpasang: QR/barcode dibuat & label tercetak | QR/label ID, record identifikasi | P-05 |
   232→| ASM-S03 | `inspected` | Lolos inspeksi/readiness (inspeksi terjadwal & hasil tercatat) | hasil inspeksi (evidence) | P-03/P-05 |
   233→| ASM-S04 | `reserved` | Direservasi untuk event/periode tertentu; konflik dicegah | record reservasi | P-05 |
   234→| ASM-S05 | `dispatched` | Check-out: picking, testing, keluar gudang dengan capture kondisi | bukti check-out (foto/catatan) | P-03/P-05 |
   235→| ASM-S06 | `in-use` | Dipakai di event (event use) | konteks event aktif; laporan lapangan | P-03 |
   236→| ASM-S07 | `returned` | Check-in kembali ke gudang | bukti check-in (foto/catatan) | P-03/P-05 |

   306→## B.3 Traceability chain (dari `ISO_IMS_BLUEPRINT.md` §3 — TARGET)
   307→
   308→Rantai lengkap, tiap mata-rantai dijelaskan:
   309→
   310→1. **requirement / clause / reference** — sumber kewajiban: kebutuhan pelanggan, klausul standar (metadata berlisensi saja), hukum/kontrak, kebijakan internal. *Bukan teks standar — hanya referensi ID + judul (REQ-040).*
   311→2. **obligation / risk** — apa yang "harus dipenuhi" atau "berisiko" jika tidak: kewajiban terjemahan dari requirement; risiko diidentifikasi via PROC-207.
   312→3. **control** — mekanisme pencegahan/deteksi: kebijakan (level dokumen D1), gate entitlement, permit HSE, gate kompetensi. Control harus menunjuk requirement yang dilayaninya.
   313→4. **process** — proses yang menjalankan control (PROC-xxx di dokumen ini). Proses = objek terhubung, bukan formulir.
   314→5. **procedure** — cara pelaksanaan tertulis (SOP, level dokumen D4) yang disetujui & effective.
   315→6. **workflow** — eksekusi terstruktur di platform: langkah, aktor, status, deadline (workflow engine Phase 15/18).
   316→7. **transaction** — kejadian bisnis nyata yang direkam: penugasan, check-out aset, submit checklist, keputusan approval. Bukan buatan untuk audit.
   317→8. **record** — data hasil transaksi yang tersimpan terstruktur (record/evidence library).
   318→9. **evidence** — record + bukti pendukung (foto, file, metadata timestamp/aktor) yang lolos evidence workflow (REQ-083) — detail `DOCUMENT_EVIDENCE_MODEL.md` §5.
   319→10. **approval / signature** — sign-off yang mengikat aktor terautentikasi, role, waktu, konteks, versi (MC §10). Kekuatan hukum = OD-103, tidak diklaim.
   320→11. **finding** — hasil pemeriksaan: audit (PROC-213), insiden (PROC-211), komplain (PROC-210) menemukan kesenjangan vs requirement/control.
   321→12. **NCR / CAPA** — ketidaksesuaian formal + tindakan korektif dengan owner & deadline (PROC-214, REQ-075).
   322→13. **effectiveness check** — verifikasi bahwa CAPA benar-benar mencegah terulangan (bukan sekadar selesai dikerjakan).
   323→14. **closure** — penutupan formal berbasis bukti; hasilnya jadi input PROC-215/216 dan pelajaran untuk proses terkait.
   324→
   325→**Contoh rantai (PROPOSED, ID contoh — bukan register nyata):** klausul-k3-manual-01 (1) → "kru wajib briefing HSE sebelum rigging" (2) → permit HSE + checklist (3) → PROC-09/PROC-203 (4) → SOP briefing lapangan (5) → workflow briefing event (6) → assignment kru ke event X (7) → record checklist terisi (8) → evidence checklist + foto briefing dengan timestamp/aktor (9) → sign-off event manager (10) → audit menemukan 1 event tanpa briefing (11) → NCR + CAPA pelatihan ulang (12) → audit ulang 3 event berikutnya lolos (13) → NCR closed dengan bukti (14).
   326→
   327→**Status rantai:** keseluruhan = TARGET `NOT FOUND` di repository (audit Phase 0); implementasi Phase 17–21; acceptance minimum = 1 rantai penuh teruji (REQ-012, REQ-070, REQ-075).
