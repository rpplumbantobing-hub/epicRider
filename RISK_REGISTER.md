# RISK REGISTER — epicRider

**Task:** WS-E (Task ID 1-e) · Phase 1 · DOCUMENTATION-ONLY.
**Status dokumen:** Register risiko produk/teknis/UX/komersial/compliance/operasional/supply. ID mulai **RSK-101** agar tidak bentrok dengan risiko audit Phase 0 **R-01..R-10** (`PHASE_0_AUDIT_REPORT.md` §7) dan gap **G-001..G-016** (`PHASE_0_GAP_REGISTER.md`).
**Penting:** Probability & Impact adalah **penilaian desk yang bersifat PROPOSED** (bukan fakta terukur). Seluruh status `OPEN` sampai mitigasi terbukti. Tidak ada angka statistik/harga/SLA di dokumen ini (anti-halusinasi MC §14).

## 1. Metodologi & skala

- Skala: High = 3, Med = 2, Low = 1. **Priority score = Impact × Probability** (maks 9).
- Urutan prioritas (rank): (1) score terbesar → (2) Impact terbesar → (3) keparahan mode kegagalan (kebocoran data/keamanan > kehilangan data > jadwal/kualitas) → (4) kedekatan materialisasi (kondisi repo saat ini).
- Risko bersifat kondisional (bergantung keputusan OD) diberi catatan eksplisit di kolom Probability/Trigger.
- Owner mitigasi memakai **role, bukan nama orang**. Bila role belum terbentuk di tim, tetap dituliskan sebagai role target.

## 3. Risiko yang memblokir Phase 2 (ringkas)

Phase 2 = architecture/domain model, threat model, data model & ADR. Blokir/risiko tertinggi:

1. **RSK-123** — `DATA_MODEL_CONCEPT.md` tidak ada (OD-116) → Phase 2 wajib membuka dengan review artefak Phase 1 atau owner menyediakan dokumen konsep.
2. **RSK-124** — OD-01 (database produksi) belum diputuskan → data model berisiko dirancang dua kali; putuskan paling lambat awal Phase 2.
3. **RSK-119** — OD-02 (strategi mobile/Windows) belum diputuskan → kontrak API (deliverable utama Phase 2 untuk kebutuhan web+mobile, REQ-020) berisiko dirancang ulang; minimal dibutuhkan arah awal.
4. **RSK-102 / RSK-103** — threat model Phase 2 wajib memperlakukan tenant isolation & entitlement sebagai scope utama; kegagalan desain di sini menghancurkan Phase 4+.
5. **RSK-101** — higiene git: commit control files Phase 1 sebelum gate Phase 2 agar baseline review jelas.

Keputusan owner yang dibutuhkan sebelum/saat Phase 2: **OD-01, OD-02 (arah awal), OD-116** (lihat `OPEN_DECISIONS.md` §3.1).
